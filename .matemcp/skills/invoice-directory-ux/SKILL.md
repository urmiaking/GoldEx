Use when modifying the enterprise invoice list, child transaction timeline, inventory movement timeline, or pagination.

Read `AGENTS.md` (especially the sections on invoice directory UI, color/typography and release notes) before editing; it is the source of truth.

## Invariants

1. Keep a semantic native table on desktop and cards on mobile, without MudTable or MudPagination. Preserve server-side filtering, sorting and the existing invoice API/commands.
2. The initial load and every page change should show responsive skeletons; yield to Blazor rendering after setting the loading flag and before starting the service request. Keep loading/error/empty states distinct.
3. Pagination choices: 10 by default, 25, 50. In RTL, size selector belongs on the right, previous/page/next on the left. Normalize old query `size=14` to 10.
4. Paid invoices have a full green success chip in both views. Background `--mud-palette-success` and foreground `--mud-palette-success-text` respect each theme's correct contrast.
5. Expanded financial details use a timeline rather than a nested table. `TransactionType.Credit` = green بستانکار, `TransactionType.Debit` = red بدهکار; do not infer polarity from the numeric amount. Stock `WarehouseActionType.In` is ورود به انبار, `Out` خروج از انبار.
6. Preserve details' independent server pagination, affected account, amount/weight, descriptions, dates and customer current/historical balances. Keep lazy visibility activation so desktop and mobile don't duplicate requests. Use unique tab/panel IDs.
7. Validate with `node --test scripts/tests/*.test.mjs`, `git diff --check`. Follow the repository's UI-only build policy and update `releases.json` with plain Persian release notes.

## Invoice settlement wizard (2026-10-30)
- The invoice form offers one main `تسویه فاکتور` action instead of the old `ثبت پرداخت` MudMenu. Existing payments have a secondary review icon with badge. Discount and extra-cost actions remain accessible separately, no payment-type shortcut may bypass the chosen direction.
- `PaymentDialog.razor` has 3 steps: choose `PaymentSide.Receive` or `PaymentSide.Pay` via explanatory, keyboard-accessible cards; choose settlement method (cash/bank, customer transfer, check, used gold, molten gold, coin; no prepayment-voucher method); then review/edit/delete and confirm all entries. Cancel closes without persisting new payment items. The same new flow works in desktop and mobile; `PaymentDialog.razor.css` owns the responsive presentation.
- For new entries the selected side is passed into `InvoicePaymentVm.PaymentSide` and `PaymentEditor.LockPaymentSide=true`; the form displays a read-only direction banner rather than allowing the user to silently reverse the chosen direction. Existing payment edit keeps the original editable side chips.
- Remaining amount within the wizard is recalculated from `TotalRemaining + _initialEffect - Items.Sum(GetBalanceEffect)` based on the original list snapshot, with different account signs for Sell vs Purchase. For editing an existing entry, the remaining before it is `CurrentRemaining + GetBalanceEffect(oldPayment)`. Do not apply the old stale `TotalRemaining` for additional entries.
- `PaymentEditor.CanApplyTotalRemaining` hides the full-balance shortcut when the selected direction would INCREASE, rather than settle, the outstanding balance. Preserve financial validation, gold fineness, exchange rates, coin valuation, check attachments, premium transfer restrictions and actual invoice accounting services.
- Local focused regression: `scripts/tests/invoice-settlement-workflow.test.mjs` and `scripts/tests/invoice-p0-redesign.test.mjs`. Authenticated visual/interaction QA remains required before release. Main GoldEx 1.0.122 remains unshipped, local Dev commit only.
## Settlement UX follow-up — compact actions, motion, no vouchers (2026-10-30)
- User rejected unlabeled clustered icon buttons and strong/bold typography. In `EditorForm.razor`, the finance header now separates the outstanding balance from a compact, fully labeled toolbar (primary `تسویه فاکتور`; review count; `تخفیف`; `مخارج جانبی`). The footer uses a primary save, secondary outline print, and separate outline delete. CSS in `EditorForm.razor.css` keeps weights <=500 and uses a 2-column grid for narrow phones. Never reintroduce a cluster of icon-only controls or three equally prominent filled actions.
- The `PaymentDialog` wizard now has EXACTLY 6 settlement method cards: InternalCash, CustomerTransfer, Check, UsedGoldInventory, MoltenGoldInventory, Coin. Remove the Apply Prepayment Voucher card, its method, related service/DTO imports, CustomerId dialog parameter and its caller wiring. Do NOT change historic voucher-linked payments, other voucher pages, or the stand-alone selector.
- In each method card the icon and method heading share one horizontal `invoice-settlement-method-top` line; description stays below. Keep restrained font weights (regular for description, 500 maximum for heading/amount) in `PaymentDialog.razor.css`.
- Every stage is wrapped in a keyed `invoice-settlement-stage`; `ChangeStepAsync` applies an exit phase (140ms) and keyed CSS entrance animation (240ms) with `prefers-reduced-motion` fallback. The async stage transition must not alter `PaymentSide` math, the original draft payments, or transaction validation.
- Focused regressions in `scripts/tests/invoice-settlement-workflow.test.mjs` and `scripts/tests/invoice-p0-redesign.test.mjs`. Client .NET build required for the transition C# changes. Authentication-dependent browser preview remains to be confirmed before deployment.

## Full invoice workspace redesign (2026-10-31)
- `EditorForm.razor[.css|.cs]` has been entirely recomposed as a card-based invoice workspace, not the legacy single MudCard/MudTabs/MudExpansionPanel form. Navigation between `invoice-core`, `invoice-customer`, `invoice-lines`, and `invoice-finance` is by freely accessible anchor steps, **not** a blocking wizard (barcode, edit, save, print, validation must all remain available). The root still owns the same validated MudForm and InvoiceVm to preserve accounting and submission semantics.
- Primary information/price-unit/date fields retain all original bind expressions, validators, trade scale and due date reminder. Customer autocomplete retains customer add/edit and balance change logic; after selection it reveals a compact summary card with type, contact, national identifier and CustomerRemaining including the current-invoice toggle. Avoid duplicating the CustomerRemaining live network control.
- The tab surface is a calculator-style compact segmented control with 4 categories (product/gold+molten, coin, currency, used gold), counts and animated state. It renders **exactly one** matching list component at a time with all original callbacks for barcode scan, stock picker, add/edit/remove and print. `EditorForm` has `_activeItemTab` and `InvoiceItemCount`; it does not clone item collections or alter price calculations.
- ProductItemsList, CoinItemsList, CurrencyItemsList and UsedProductsList now use semantic, scrollable, low-ink desktop HTML tables and separate compact mobile cards, retaining financial columns and all operation callbacks. All shared list styling lives in `EditorForm.razor.css` under `.invoice-workspace ::deep` because child Razor components need scoped CSS penetration; don't reintroduce MudTable or icon-only opaque primary actions. Empty states include useful add guidance.
- The former bottom MudExpansionPanel was removed. The live invoice finance sidebar is always visible and sticky on desktop (not sticky on tablet/mobile). It reads **directly** from existing InvoiceVm calculated totals: final invoice amount, remaining, raw values, wages, profit, tax, discount, extra costs, used gold (when present), received, paid. Actions are pill-shaped settlement, existing settlements, discounts and expenses; prevent a new settlement when there are no invoice items, matching former conditional availability. The unit-switch popover and existing invoice totals remain wired to the same ViewModel.
- Footer save/print/delete controls retain original handlers and positive-only deletion confirmation; release 1.0.122 consolidated notes. For QA run `node --test scripts/tests/invoice-workspace-redesign.test.mjs scripts/tests/invoice-p0-redesign.test.mjs scripts/tests/invoice-settlement-workflow.test.mjs scripts/tests/invoice-adjustment-dialogs.test.mjs` and a client build for Razor structural changes. Authenticated desktop/mobile browser interaction still required before any production publish.
