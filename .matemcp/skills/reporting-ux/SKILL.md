# GoldEx Enterprise Reporting UX

## Report page routing
- `Pages/Reporting/Index.razor` and the 14 `Pages/Reporting/Pages/Reports/*.razor` use the shared AppBar breadcrumb; do not reintroduce page-local `MudBreadcrumbs`. Their `MudContainer` carries `gex-report-page` for scoped legacy-report styling in `appearance.css`.
- Legacy report tables (13 report views) retain existing report DTOs, sorting, actions and printing. They have neutral `Elevation=0` and common lighter typography/spacing. This is transitional; their full per-report mobile card migrations are not yet complete. Never confuse a cosmetic table restyle with a replacement.

## Shared report filter
- `Components/ReportFiltersBase.razor[.css]` owns the header/filter grid, 1 date range picker (RTL leading calendar icon, `gex-filter-date-range`), responsive desktop/mobile apply action and existing `EditForm`/DataAnnotations validation. Report-specific `Filters/*.razor` supply their own MudItem fields via `ChildContent`.
- `OnSubmit.InvokeAsync(Model)` must occur only on valid submit. Maintain original filter DTO and API business query; date start/end and print URL semantics remain unchanged.
- CSS typography defaults 400 for prose, 500 headings/controls, no heavy shadows.

## Customer balance report first full migration
- `Components/Views/CustomerBalanceReportView.razor[.cs|.css]` has a semantic desktop table and compact mobile customer cards with Blazor Virtualize (no paginator), name/payable/receivable/net sorting, source navigation, one shared print action.
- Its `CustomerBalanceReportSummary` still groups **all Items** by price unit; never base ledger totals on rendered virtual rows. Existing positive/negative sign formatting, names and ledger navigation are preserved.
- `Items` may be replaced as filters change: rebuild the sorted virtualized item list then. `@key=row` avoids duplicate render keys if a customer appears with different currencies.
- Print route/components `ReportPrintBase`, `ReportBase` and all print markup were untouched.

## Enterprise report print system (2026-10-30)
- All **14** authenticated reporting print routes under `Pages/Reporting/Pages/Prints/*ReportPrint.razor` continue to call one `Components/ReportPrintBase.razor`. That shared component now owns the full premium branded document sheet (GoldEx wordmark; tenant store name, optional store logo/address/phone; report title, date range, time, genuine row count where the source is an ICollection; KPIs from the *actual first SummarySection*; original child table; full original ReportSummary; notes and footer).
- Do not hard-code fake amounts/percentages or sum different currencies. KPI unit scope MUST be visible via the first summary section title; complete multi-unit totals remain grouped in the bottom ReportSummary. If no summary exists, render a safe row-count card only when count is available.
- `GoldEx.Server/wwwroot/css/reports/report-enterprise.css` is loaded by ReportPrintBase after the legacy report CSS so that it can safely override their original blue header, heavy shadows and crowded summary. Uses self-hosted Vazirmatn. Maintain stable A4 portrait, the named A4 landscape page for reports with 7+ columns, CSS `@page` page/pagination counters, repeated `thead` on each print page, safe row breaks, low-ink gold accents, subtle watermark, monochrome-friendly contrast.
- Landscape route parameters explicitly set on CoinInventory, CustomerTransactions, LedgerAccountDetails, ProductInventory, SellInvoice and ProfitAnalysis. Do not landscape 3-6-column reports without a reason. Do not change the underlying report columns or finance formulae, receipt printing, or DevExpress invoice report designer.
- `Client/wwwroot/js/report-print.js` waits for CSS, document fonts, and optional store logo before showing print dialog, and closes only the popup after printing. Avoid arbitrary fixed 500ms races.
- The enterprise print page is **not a one-page poster**: it may span many A4 pages with repeated table headers and page numbers. Breaks must not cut rows, but the entire report must never be clipped to a fixed viewport or a single page.
- Verification: `node --test scripts/tests/enterprise-report-print.test.mjs` checks all 14 routes and exact landscape mapping. Structural client compilation successful. Actual signed-in browser print/PDF preview for a long multi-page report is a necessary deployment validation. No push/deploy by default; GoldEx version 1.0.122 remains unshipped.
## Persian digits in printed reports (2026-10-30)
- All 14 print views inherit `ReportPrintBase`; after data has rendered, `printAndClose()` calls `window.localizeGoldExReportDigits()` before opening the browser print dialog. The function in `Client/wwwroot/js/report-print.js` uses a scoped `TreeWalker(SHOW_TEXT)` on `.gex-print-document` to turn Latin `0-9` and Arabic-Indic `٠-٩` into Persian `۰-۹`. It touches only text nodes, not values sent to services, hrefs, input values, scripts or styles. Never mutate accounting totals, APIs, filter parameters or identifiers.
- CSS page-margin page/page-count counters are not part of the HTML DOM. `report-enterprise.css` declares the `gex-persian-page` numeric counter style and an IRANSans FaNum fallback for generated margin text. The print CSS cache key is v2.
- Test with `scripts/tests/enterprise-report-persian-digits.test.mjs` + `scripts/tests/enterprise-report-print.test.mjs`. Regression cases include decimals, grouped currency amounts, grams, historical dates, barcode/phone display, Arabic digits, idempotence, and not editing scripts/styles/attributes. Actual PDF preview of page-margin counters should be checked in Edge/Chrome before production.
