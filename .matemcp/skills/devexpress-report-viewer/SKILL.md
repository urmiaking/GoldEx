# DevExpress GoldEx Report Viewer Styling

The GoldEx invoice viewer is `DxWasmDocumentViewer` from DevExpress Blazor JSBasedControls 24.2.7, NOT the newer native `DxReportViewer` with OnCustomizeToolbar. Official DevExpress technique: customize CSS palette classes prefixed by `.dx-designer-viewport .dxd-*`, per https://docs.devexpress.com/XtraReports/400413/web-reporting/asp-net-core-reporting/document-viewer-in-asp-net-applications/customization/customize-the-document-viewer-color-scheme .

- The invoice preview is `src/App/Client/GoldEx.Client/Pages/Invoices/Viewer.razor`, with an isolated `gex-report-viewer` wrapper. `src/App/Server/GoldEx.Server/Components/App.razor` links `wwwroot/css/devexpress-goldex.css` after appearance.css.
- All CSS selectors are scoped under `.gex-report-viewer`. Use CSS variables from existing MudBlazor palette, including surface, background, text, primary, primary-text and border, to support every GoldEx theme. Style the official dxd palette, toolbar, right tab panel and search/inputs; do not reimplement the viewer.
- Never override report document bricks, page contents, PDFs, or invoices themselves. Avoid `overflow:hidden` on the outer wrapper because export menus and overlays can be clipped. Keep print/zoom/export and `reportingCustomization.onBeforeRender` (zoom=0) unchanged. Do not edit package/vendor CSS.
- Test `node --test scripts/tests/devexpress-report-theme.test.mjs` and full regression suite. Headless Chrome fixture with DevExpress's actual 24.2.7 stylesheet confirmed distinct light/dark surfaces and the toolbar's glass blur.
- Running localhost may still serve an OLD compiled App.razor; a CSS file returning HTTP 200 alone does NOT mean it is referenced in the live document. After the next client/server build/restart, verify new stylesheet link and authenticated report UI.
- Release 1.0.117, GitHub issue #269. Commit to local Dev only unless the user requests push.

## Follow-up #270: real responsive toolbar + icons
- Do not treat overflow-x:auto alone as a solution. DevExpress 24.2.7 toolbar is a centered Flex item with overflow:hidden and its own min/fit-content sizing. Mobile scroller requires overflow-x:auto!important, justify-content:flex-start!important, direction:ltr, auto scroll behavior, a max-content non-shrinking toolbar with margin 0. Chrome regression actually asserted scrollLeft=175 with scrollWidth=971 and clientWidth=498 at mobile viewport.
- Additional theme-aware CSS in wwwroot/css/devexpress-viewer-responsive.css is linked AFTER devexpress-goldex.css. Explicitly style Zoom/Page inputs including -webkit-text-fill-color to fix light-on-light in dark mode. No globally applied DevExpress theme rules; only gex-report-viewer.
- Blazor DxWasmDocumentViewer 24.2.7 has documented DxDocumentViewerCallbacks.CustomizeMenuActions. reporting-customization.js registers static text/html SVG templates for print/search/export/fullscreen/zoom and assigns imageTemplateName to supported action IDs, leaving execute intact. BeforeRender uses zoom=-1 (Page Width) under 960 px and zoom=0 (Whole Page) on desktop. This is the correct documented API for changing built-in command icons; never overwrite the vendor JS or reimplement native export.
- Run scripts/tests/devexpress-responsive-viewer.test.mjs, scripts/tests/devexpress-viewer-mobile-qa.ps1 (Windows headless Chrome + exact installed vendor CSS) and full Node suite. Live authenticated print/export still needs visual QA. Release 1.0.118, issue #270.
## #271: Export dropdown, compact pager, visible light-theme icons
- ExportTo is a complex dropdown, unlike normal toolbar actions. In onCustomizeMenuActions use e.GetById(ActionId.ExportTo).items()[0].imageTemplateName (documented in DevExpress Support T1107801), with fallback for items array/flat command. Never replace native clickAction; keep export formats.
- Hide redundant FirstPage, LastPage, MultipageToggle (visible=false), retain native PrevPage / Pagination / NextPage, and use built-in page selector with compact styling. This replaces the cluttered multi-arrow UI without sacrificing navigation.
- Light sidebar hover issue is vendor dxd-back-highlighted:hover setting icon fill WHITE against light surface. Scope hover and selected overrides to .gex-report-viewer .dxrd-right-tabs in css/devexpress-viewer-fixes.css; it is linked AFTER responsive CSS. Selected uses var(--gex-report-accent) and contrast var(--gex-report-accent-ink), not DevExpress blue. Real Chrome fixture verified idle fill rgb(36,38,41) and selected background rgb(155,103,0) with white icon.
- Run scripts/tests/devexpress-viewer-fixes.test.mjs and full Node tests; main enterprise release 1.0.119; issue #271.
## #272 — One-line toolbar, RTL pager and localization
- Regressions in #271 arose because the 64px DevExpress toolbar did not force nowrap when page selector padding changed: picker fell to second row. In devexpress-viewer-fixes.css, keep .dxrd-toolbar flex, flex-wrap:nowrap, white-space:nowrap, 64px, max-content and its .dxrd-preview-pager inline-flex/64px; wrapper overflow-x:auto at all widths while mobile can still swipe. Verified real Chrome with package CSS: pagers in same row at 460/1280/1720px.
- Previous/Next icons' SVG directions were backwards in RTL: previous must point right, next left. Native handler IDs unchanged. Test coverage in devexpress-viewer-rtl-localization.test.mjs.
- To localize viewer UI, use installed-v24.2.7-supported DxDocumentViewerCallbacks.CustomizeLocalization and sender.UpdateLocalization with case-sensitive English text keys and Persian UI strings. Do not replace DOM text or rewrite report/PDF. Targeted dictionary localizes common viewer labels only, not every specialized DevExpress resource (a complete pack would require vendor localization dictionaries).
- .dxrd-print-dialog .dx-overlay-content receives a short opening animation unless prefers-reduced-motion. This affects the DevExpress options dialog, not the OS/browser print window. Chrome QA in scripts/tests/devexpress-viewer-layout-qa.ps1 verifies animationName.
- Release 1.0.120, issue #272. Local Dev commit; no push without user request.
